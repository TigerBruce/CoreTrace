# CoreTrace

双击桌面“CoreTrace”快捷方式进入编辑模式。拖动标题栏移动，拖动四边或四角改变长宽，无需输入像素。图表自动重新排列；为完整显示所有核心与内存前五，最小高度随宽度变化。

编辑工具栏：主题、暂停/继续、20秒/40秒/1分钟循环切换、确认固定。

确认固定后隐藏标题栏、工具栏和缩放边框，仅CPU总体卡片左上角保留小铅笔按钮。点击铅笔重新编辑。托盘菜单也可编辑、固定、隐藏或退出。固定时窗口放在普通应用后方、桌面前方，不再嵌入 Explorer WorkerW，避免桌面层截获编辑按钮；普通应用可覆盖它。

CPU 总体与内存相邻，每核小图按 P/E 分组。蓝色为负载面积，温度线 <65°C 绿、65–<80°C 橙、≥80°C 红。内存右侧为固件报告的配置工作速率 MT/s，启动读取一次，并非实时控制器时钟。

只显示内存占用前五，已删除固定关注程序及对应采样字段。前五按同名进程合并的私有工作集统计。历史保留70条、最长1分钟显示，不保存磁盘日志、不联网。

无滚动条，所有卡片在可视区自适应排布。暂停仅冻结显示；编辑时悬停曲线可查看当时CPU前五。

原生 Windows 10/11 x64 C++ / Win32 程序。源码 native-src，离线构建 build.cmd。便携运行只需 native-portable 文件夹；已安装的官方 PawnIO 为温度频率读取依赖。当前硬件传感器支持已实现的 Intel Alder/Raptor Lake 型号，本机 i5-14600K 已验证。

此前版本的性能数据保留在 docs，不能作为此版长期稳定性结论；长时间测试按用户要求未启动。

CPU总体和内存卡片同步调节高度：编辑模式下只需拖动CPU总体卡片下边缘的短横线，两张卡片始终等高。内存前五为独立卡片，拖动其上边缘短横线可上下调节；卡片变大时字体自动增大。可调上限受总窗口剩余空间限制，可先拉高整体窗口。下面核心小图继续分配剩余高度，确认固定后保存。
内存前五使用相同比例的横向柱形图，最大占用为满长，其余按相对占用绘制，右侧保留内存量和物理内存百分比。

编辑模式提供外框透明、卡片透明两个独立滑杆（0–80%，0%完全不透明），以及全局字号12–22。拖动实时预览，松开/确认固定后保存，重开保留。字号影响正文、标题、图表标注及排行文字；排行仍随自身高度放大，并限制在行内避免覆盖柱形图。字号变大时必要时增加窗口最小高度。
外框/背景与卡片底色分别调节透明度，文字和曲线保持清晰；固定/编辑切换保留。托盘菜单“恢复不透明”可直接恢复。透明显示使用原生窗口像素合成，不新增持续动画或高频采样。字体可在底部菜单选择。

编辑菜单及透明度/字号滑杆位于最底部。确认固定只收起底部编辑区和窗口外框，图表客户区原点及尺寸保持不变；重新编辑恢复底部菜单，不缩放图表。配置尺寸记录图表内容区，避免重复切换后尺寸累积变化。

编辑模式下，上方系统标题栏和底部菜单栏空白处均可移动窗口。底部拖动采用独立移动处理，可将图表内容贴近屏幕工作区上沿；按钮、确认区和滑杆不触发移动。P/E组之间独立保留18像素间距，参与宽度换列、最小高度和剩余空间计算。

底部编辑菜单新增红色“退出”按钮，点击保存设置并退出程序。固定模式下先点CPU卡片左上角铅笔打开编辑区，也可从托盘菜单退出。

视觉整理：移除曲线上的时间端点和重复数值刻度，显示范围仍从底部菜单切换，编辑时悬停仍可查看历史。网格减淡并减少分割线，核心频率改用次要文字颜色，内存排行柱形统一圆角。没有新增动画或刷新定时器。

目录说明：native-portable 是可复制到其他电脑的运行目录；native-src 是源码和图标源文件；tools 是修改程序时使用的离线编译工具，日常运行不需要；docs 是压缩后的测试截图和记录，日常运行不需要。已删除编译工具的重复下载压缩包，历史 BMP 截图已无损转换为 PNG，并移出运行目录。

CPU 统计方式可在编辑区底部的“CPU 统计”菜单或托盘右键菜单切换，设置会保存。默认“任务管理器（Utility）”：总体直接读取 Windows Processor Information(_Total) 的 % Processor Utility，数值和图表限制在 0–100%；每个物理核心取其逻辑线程 Utility 最大值。另一选项“忙碌时间（Time）”保留原算法：总体平均所有逻辑处理器的 % Processor Time，每核取最忙线程。两种指标在同一次采样中采集并保存于现有70帧内存历史，切换时全部历史同步改变，暂停期间也可切换，不混合口径。悬停的应用 CPU 前五仍是忙碌时间并明确标注。Utility 对齐本机 Windows 任务管理器的统计口径，独立采样可能存在短时差异；不同 Windows 版本的任务管理器可能使用不同口径。两种模式都不代表物理计算资源已全部耗尽，也不限定为某一个应用。

在其他电脑修改与编译：请参阅 [BUILDING.md](BUILDING.md)。仓库排除编译器、生成文件及本机配置，保留可重新构建应用的源码和必要资源。
